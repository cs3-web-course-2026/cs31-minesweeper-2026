# Практична робота №2. Логіка та інтерактивність гри у JavaScript та DOM

## Мета роботи
Ознайомитися з основними структурами даних у JavaScript (масиви, об’єкти, примітиви) та навчитися реалізовувати комплексну логіку застосунку через функції на прикладі гри Minesweeper. Закріпити навички роботи з об’єктною моделлю документа (DOM) у веб-браузері, навчитися реалізовувати інтерактивні елементи інтерфейсу, опанувати принципи обробки подій користувача (Event Handling) та навчитися динамічно оновлювати відображення даних без перезавантаження сторінки. Засвоїти принципи побудови логіки застосунку та її поетапної інтеграції з візуальним представленням.

## Завдання
Необхідно розробити внутрішню логіку гри Minesweeper засобами JavaScript, а потім інтегрувати її з веб-інтерфейсом, забезпечивши повну взаємодію користувача з ігровим процесом через браузер. Виконуйте кроки послідовно — кожен наступний крок спирається на результат попереднього.

### Крок 1. Моделювання даних (Data Layer)
Перш ніж писати функції, потрібно визначити, як програма «бачить» гру.

* **Об'єкт стану гри (`gameState`):** Має зберігати глобальні параметри: розмір поля (`rows`, `cols`), кількість мін, поточний статус (`'process'`, `'win'`, `'lose'`) та час гри.

```javascript 
{
  rows: 10,
  cols: 10,
  minesCount: 15, // Налаштування складності
  status: 'process', // Поточний стан гри: 'process' | 'win' | 'lose'
  gameTime: 0, // Час гри у секундах
  timerId: null, // Посилання на ідентифікатор таймера для його зупинки (clearInterval)
};
```

* **Двовимірний масив поля:** Це сітка, де кожен елемент — об'єкт клітинки з такими властивостями:
    * `type`: вміст клітинки (`'empty'` або `'mine'`).
    * `state`: стан відображення (`'closed'`, `'opened'` або `'flagged'`).
    * `neighborMines`: кількість мін у сусідніх клітинках (число від $0$ до $8$).

```javascript 
{ 
  type: 'mine', // Вміст клітинки 
  neighborMines: 0, // Скільки мін навколо? 
  state: 'closed', // Стани: 'closed', 'opened', 'flagged' 
}
```

### Крок 2. Генерація поля та мін
Реалізуйте функцію `generateField(rows, cols, minesCount)`:
1.  **Ініціалізація:** Створіть порожню сітку, де кожна клітинка має `type: 'empty'` та `state: 'closed'`.
2.  **Розстановка мін:** Випадковим чином оберіть координати $(x, y)$ та змініть їхній тип на `type: 'mine'`.
    > **Порада:** Використовуйте `Math.random()`. Слідкуйте, щоб дві міни не потрапили в одну й ту саму клітинку.

### Крок 3. Алгоритмічна частина (Business Logic)
Це «серце» вашого застосунку, де описуються правила гри.

* **Підрахунок сусідів (`countNeighbourMines`):** Пройдіть по кожній клітинці з типом `'empty'`. Перевірте всі 8 сусідніх позицій та запишіть їхню суму у `neighborMines`.
    
* **Логіка відкриття (`openCell`):**
    * Якщо `state` клітинки вже `'opened'` або `'flagged'` — нічого не робити.
    * Якщо клітинка має `type: 'mine'` — змінюємо статус гри на `'lose'`.
    * **Рекурсія:** Якщо клітинка порожня (`neighborMines === 0`), має спрацювати рекурсія: автоматично змінити `state` на `'opened'` для всіх сусідів, і так далі, поки не зустрінете клітинки з цифрами.

### Крок 4. Таймер та прапорці
* **Прапорці:** Функція `toggleFlag(row, col)` має змінювати `state` клітинки з `'closed'` на `'flagged'` і навпаки. Якщо клітинка вже `'opened'`, ставити прапорець не можна.
* **Час:** Використовуйте `setInterval`, щоб щосекунди додавати $1$ до лічильника часу в `gameState`. Обов'язково зупиняйте таймер (`clearInterval`), коли гра переходить у статус `'win'` або `'lose'`.

> На цьому етапі логічний шар гри повністю готовий і його можна перевірити через консоль браузера, ще без візуального інтерфейсу.

### Крок 5. Рендеринг ігрового поля (DOM)
Реалізуйте функцію, яка на основі масиву даних (створеного у Кроці 1-2) динамічно генерує HTML-структуру ігрової сітки.

### Крок 6. Динамічні елементи інтерфейсу
Налаштуйте динамічне оновлення таких елементів:
* Таймер (відображення секунд під час гри).
* Лічильник доступних прапорців.
* Кнопка «Старт/Рестарт» для скидання стану та створення нової гри.

### Крок 7. Обробка подій користувача (Mouse Events)
* **Лівий клік:** Відкриття клітинки. Якщо це міна — гра закінчується, якщо порожня — спрацьовує рекурсивне відкриття (Крок 3).
* **Правий клік:** Встановлення або зняття прапорця (`state: 'flagged'`). Необхідно заблокувати стандартне контекстне меню браузера.

### Крок 8. Завершення гри
Реалізуйте перевірку умов перемоги (всі безпечні клітинки відкриті) або поразки (підрив на міні) з відповідним візуальним сповіщенням користувача.

## Система оцінювання
* **Моделювання даних та ініціалізація:** 1 бал (правильна модель клітинки та ігрового поля — Крок 1).
* **Генерація поля та розрахунок мін:** 1 бал (функції `generateField` та `countNeighbourMines` — Крок 2-3).
* **Механіка гри, рекурсія та обробка стану Win/Lose:** 2 бали (функція `openCell`, рекурсивне відкриття, переходи статусу гри — Крок 3, Крок 8).
* **Таймер, прапорці та допоміжні функції:** 1 бал (логіка `toggleFlag` та лічильника часу — Крок 4).
* **Рендеринг ігрового поля (DOM):** 1 бал (коректне створення сітки на основі даних логічного шару — Крок 5).
* **Динамічні елементи інтерфейсу:** 1 бал (оновлення таймера, лічильника прапорців та робота кнопки перезапуску — Крок 6).
* **Обробка подій та ігрова механіка:** 2 бали (правильна реакція на кліки, блокування контекстного меню — Крок 7).
* **Якість коду:** 3 бали (чистота коду, розділення логіки та маніпуляцій з DOM, дотримання принципів DRY/KISS/YAGNI, зрозумілі назви змінних та функцій, відсутність дублювання).
* **Якісне проведення рецензування (Code Review):** 3 бали (глибина аналізу коду іншого студента, корисні зауваження та пропозиції).

**Максимальна кількість балів: 15.**

> **Примітка:** Робота оцінюється лише за умови наявності звіту.
